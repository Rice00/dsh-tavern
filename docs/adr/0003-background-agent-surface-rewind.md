# 后台 Agent 使用单 Session 与 Surface 回退

后台候选与状态结算在一条 Tavern 对话正常向前推进时复用同一个后台 Session。正文回退或替代时，Tavern 通常根据 checkpoint 保存的闭合回合边界，用 DSH `surface replace` 遮蔽其后的后台消息，再注入最新权威状态继续运行。这与前台 Agent 的既有回退机制一致，保留连续记忆和单一轨迹，同时由 Tavern revision 校验阻止旧任务结果落盘。

Tavern Compaction 同时压缩前台和后台 Session，但使用不同摘要契约：前台使用 Tavern 剧情压缩提示词，后台直接使用 DSH 内置提示词。两边结果独立记录，单边失败报告为部分成功；外部维护操作不得在后台 Agent 忙碌时开始压缩，压缩期间也不得启动新的后台任务。

后台 Session 一旦开始压缩，后续如果发生正文回退或替代，Tavern 不再尝试对该 Session 的 compact summary 做 Surface 回退，而是从 Story Timeline 的权威状态重建一个后台 Session。保护标记在命令发出前持久化，因此即使压缩成功但客户端丢失完成响应，也不会让包含废弃剧情的摘要进入新分支。代价是压缩后的首次回退会失去旧后台 Session 的连续轨迹；这是为了优先保证剧情分支正确性。

后台任务内部的上下文容量保护不走外部维护队列：每步按当前任务模型窗口检查输入估算、本步待加入消息和输出预留额度，合计达到容量时调用原生当前回合压缩。服务端确认上下文超限时，同样允许原生压缩与有限重试，不能被手动压缩策略屏蔽。两条路径都先持久化上述回退保护标记；不启动新的后台 Agent，不等待当前任务自己结束。Token Meter 是估算，模型窗口未知或估算偏低时由服务端超限恢复兜底；无可压缩历史或重试耗尽时仍报告原错误。

## 历史加载性能边界

后台 Agent 不按事件数量自动分段，始终保持一条连续 Session。DSH 会把模型流式返回的一两个字、词或标点分别记为逻辑事件；一次玩家行动触发多个后台任务时，可能快速累积数万个事件。当前 DSH 历史接口按完整消息数量分页，却会展开并传输这些细粒度事件，因此打开后台对话可能长时间停留在“载入历史”，并偶发 `Failed to fetch`。

这是 DSH 历史读取与分页的上游性能问题，不通过拆分 Tavern 后台 Session 规避。后续应由 DSH 在普通对话历史中合并或省略已完成回复的流式片段，并对事件数量或响应体积设置上限；原始细粒度事件只在轨迹调试时按需读取。

## 非模型消息与 Token Meter（2026-09-07）

种子轨迹的助手确认消息、回退的空 Surface 替换、重新生成的正文替换都不是一次新的模型调用，可能在没有活动 `step/start` 的情况下追加。当前 DSH Token Meter 将所有 `assistant/message` 都视为模型步骤输出，因此回放这类事件时抛出 `has no matching step/start event`，前后台压缩都会受影响。

`tavern-token-meter.js` 在统计边界识别这些无 usage 的 Tavern 注入或替换：种子使用专属来源和 ID；旧替换限于 Tavern 预设，且必须引用替换范围内的既有消息节点，而非模型流式 chunk。仅交给原生 Token Meter 的计量事件视图使用非模型注入入口，保留助手角色、内容、seq 和 Surface 替换范围，不建立虚假的 provider usage anchor。Session 原始事件、请求、显示和回退语义不变，已有会话无须迁移。

这是针对上游 `_foldEvent` 的局部兼容适配，随插件卸载恢复；未知接口明确报错。真实模型缺步骤、含 usage 的异常回复及非 Tavern 替换仍由原生校验拒绝。未来上游原生支持非步骤消息后，应移除此适配。原生集成测试覆盖失败后重新统计、种子、回退、正文替换、完整手动压缩及历史不变；摘要输出使用固定测试值，不代表真实摘要质量。


## 固定系统背景与压缩边界

人物卡、常驻世界书和开局固定偏好通过原生 `system-prompt/assemble` 进入前后台系统上下文，由 DSH 写入 `request/header.system`。动态世界书和本轮要求仍进入 Frame。原生压缩替换剧情 Surface，不修改系统背景。

开局快照仍用原生 `user/message` 持久化，但正文为空，背景存于 `source.fixedSystemText` 和来源分段。它是快照载体，不作为历史正文发送或摘要材料；读取原始事件可在压缩、恢复和原生分叉后重建相同系统上下文，不依赖额外文件或当前卡片内容。

旧版本已有正文前缀时，追加空正文快照并用原生 Surface 替换移出旧前缀，不修改原始事件。前缀已被摘要覆盖时，从原始事件恢复固定背景；已有摘要保留，避免误删剧情。旧 EJS 前缀迁移时沿用已求值的开局快照，之后固定。切换到这套布局的首次请求会改变缓存前缀，后续正常复用。
