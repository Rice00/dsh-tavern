# Tavern 原生世界书激活设计

> 已实现；ST 语义参考固定提交 `8172dcd0ee672d3cd9a5e5f7af134f91a45cd2b8`。
> DSH 仍保留每轮最多 5 条非常驻条目及既有 10 轮冷却，不承诺完整 ST 提示词兼容。

## 运行链路

正文准备时读取一次当前绑定世界书，扫描当前玩家输入及最近历史，并加入脚本显式提供的扫描文本。选取和模板投影使用同一份世界书。玩家输入经过现有宏和输入正则投影后参与匹配。

正文完成后的世界书准备仅保存下一轮预览；正式请求按当前输入重新计算，不消费预览的结果或冷却。开场预览也不代替正式匹配。请求准备时记录最终有渲染输出的非常驻条目；同一操作的重试复用已保存的 ForegroundFrame。

代码入口：

- `worldbook-activation.js`：扫描、关键词、递归、包含组、选取优先级与文本顺序。
- `worldbook-recall.js`：既有冷却和 EJS/宏投影。
- `foreground-worldbook.js`：一次正式请求的世界书快照、激活与渲染。
- `turn-orchestration.js`：将结果接入正式 ForegroundFrame。

## 扫描与关键词

默认扫描最近 **2 条消息**，包括当前玩家输入，不是 2 个对话回合。

- 世界书 `scan_depth` 控制默认消息数；条目 `scanDepth` / `extensions.scan_depth` 覆盖它。
- 留空跟随世界书，0 不扫描；最大 1000 条消息。
- 主关键词是完整字符串，不拆字、不对未激活条目进行全文检索。
- 支持合法正则、大小写、整词，以及四种副关键词逻辑：AND_ANY、NOT_ALL、NOT_ANY、AND_ALL。
- 普通短关键词不被任意禁止；整词规则参考 ST，包含中文和多词短语的处理。

## 递归与包含组

世界书 `recursive_scanning` 开启递归，默认关闭。已选中的常驻和非常驻正文可进入后续扫描；未入选条目不能成为递归来源。

- `preventRecursion`：不向递归扫描贡献正文。
- `excludeRecursion`：不在递归阶段激活。
- `delayUntilRecursion`：仅在达到指定递归等级后参与。
- 每条最多激活一次，循环受条目数和延迟等级数限制。

包含组支持逗号分隔的多个组、关键词计分、`groupOverride` 优先选取、`groupWeight` 权重抽选。同组已选条目阻止后续递归轮次加入其他成员。未配置优先覆盖时使用本地随机抽选，不调用模型；已保存的 Frame 不重新抽选。

概率和作者时间效果本次不启用。

## 五条上限与十轮冷却

非常驻条目每轮最多选 5 条，玩家输入与脚本扫描共用此上限。常驻条目不占五条额度。超出上限时优先选择较大 `order`，诊断记录 `limit`。

保留既有冷却算法：第 N 轮记录的条目在 N+1 至 N+10 冷却，N+11 恢复；同轮可复用，正文指纹变化立即解除。回退继续通过 Story Timeline checkpoint 恢复记录。没有引入作者 cooldown/sticky/delay，也没有新去重系统。

旧版本已经记录过的下一轮预览，在首次正式计算时释放该预览的记录后重新筛选，避免升级时误排除尚未发送的条目。

## 最终文本顺序与蓝绿灯结构

选择优先级与文本编排分开。同一位置内按 ST 的降序选择、头部插入方式编排，最终低 `order` 在前；相同 `order` 按选择顺序反向排列。

为保持蓝灯开闭标签能包住绿灯内容，同一位置的条目必须一起投影：

- 某位置存在启用的非常驻条目，或者存在包含组竞争，该位置的常驻条目随激活结果一起进入前台动态 Frame。
- 只有普通常驻条目的位置仍进入系统前缀。
- 划分由条目配置决定，不随本轮是否命中改变，避免常驻内容在前缀与后部之间来回移动。
- `[mvu_update]` 仍留给 MVU 规则链，不进入前台正文。

EJS 与宏按最终编排顺序运行；失败条目产生诊断，不发送模板源码，也不记录该条目的冷却。

这里的 `position`，以及 at-depth 条目的 `depth/role`，用于保持分组边界，**不等于已经实现 ST 的精确消息锚点**。动态 Frame 仍沿用 DSH 的 user 消息承载方式；没有改为中途 system。

## 诊断与限制

每次正式正文操作单独保存详细日志：`worldbook-recalls/<chatId>/<operationId>.json`。游玩页「导出 → 世界书召回日志」下载当前分支最近一次记录；调试工具的 `worldbook` 层可按轮次读取。旧轮次没有记录时明确返回缺失，不用当前卡片反推。

日志包括扫描范围、命中关键词及其输入/历史/递归来源片段、主副关键词条件、优先级与最终输出顺序、组竞争胜者、冷却依据、五条截断前的入选项，以及禁用、空正文、MVU 专用条目的排除原因。选取顺序使用 `order` 降序、`displayIndex` 升序，最终文本在各位置内反向编排。

选中与发送分开记录：条目可能因模板失败或输出为空而没有注入。`outputs` 保存渲染正文和位置；实际模型请求到达时标记 `requested`、关联请求 ID，并核对前台输出是否出现在请求 Frame 中。系统前缀输出的核对值为 `null`，不冒充已经核实。

详细日志独立存储，不进入模型提示词；Frame 只保留简要诊断和日志路径。日志写入失败不阻断正文，错误记在 Frame 收据中。目前提供 JSON 导出，尚无逐条可视化调试器。

目前未执行概率、作者 timed effects、向量、automation、outlet、人物过滤、最小激活数扩展扫描和精确位置注入。世界书与条目编辑保留未支持字段。多世界书合并仍以主书的书级设置为准，条目扫描深度可以覆盖默认值。

此设计保留重复注入节省，不承诺缓存命中率。混合位置中的常驻内容会出现在动态 Frame；修改常驻独立区块仍可能改变系统前缀。模型端缓存效果需要真实请求 usage 验证。
