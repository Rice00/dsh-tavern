# 场景写作 Skill 与用途分配

2026-09-14：本设计取代原“卡片专用文风库”方案。

## 使用流程

“剧本与素材库”存放剧本、教学材料等文本。导入仅保存文件，不启动 Agent、不生成 Skill。用户在卡片工作台引用材料并明确要求编写写作 Skill，卡片 Agent 加载 `tavern-create-writing-skill`，依据材料中的现成教导组织写法。适用场景、排除场景或偏好不明确时，在制作过程中询问用户。

成品是独立 Skill：入口和配套 `references/*.md` 包含运行所需的内容。素材删除、改名或修改不影响已保存的 Skill，也不自动同步它。

## Skill 库

统一管理内置和自建 Skill，查看入口与参考内容、调整用途、自建项删除。卡片 Agent、前台 Agent、后台 Agent 分开分配，可多选；取消全部分配即停用。初版全局适用于所有游戏，不绑定人物卡。

默认用途：卡片制作 Skill 给卡片 Agent；场景写作 Skill 给前台；后台任务 Skill 给后台。已有自建 Skill 保持卡片用途，内置后台人物设计 Skill 保持后台用途。用户分配覆盖默认值。

## 加载与边界

复用 DSH 原生 SkillRegistry、FileSystemSkillProvider 和 `skill` 工具。Tavern Provider 根据当前 Agent 的用途过滤目录和加载请求，原生目录只披露名称与简介，命中后才加载正文。详细参考通过只读 `tavern_read_skill_reference` 按需读取，该工具检查当前用途和文件归属。前台自动完成场景选择，无需用户手动选择或确认。

用途分配不会增加 shell、文件编辑或后台提交权限。生图与手机专用任务仍沿用原有工具限制。取消分配阻止后续发现与加载，不追溯抹除历史中已经加载的内容。

## 存储与更新

自建 Skill 位于 Tavern 持久数据的 `skills/<name>/`。`metadata.tavern.purpose` 保存默认用途；`.assignments.json` 保存用户的分配覆盖，包括内置项。原生文件监听与保存后的显式失效通知使目录刷新。

保存校验名称和参考相对路径；参考内容由保存工具写入独立目录。覆盖时省略 references 保留已有文件，提供数组则替换整套参考文件。参考读取拒绝指向 Skill 之外的符号链接。
