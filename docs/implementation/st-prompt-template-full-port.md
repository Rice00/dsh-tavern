## 运行位置

上游使用浏览器 DOM、jQuery、浏览器 Function/iframe，以及共享模块状态。直接在 DSH Node 进程执行既不能提供页面环境，也会改变当前模板的执行边界；继续套用现有 QuickJS 局部函数则无法运行整包。

完整插件应运行在专属浏览器执行环境，以一条 Tavern 会话为实例，设置面板和编辑器使用同一实例。不得在每个消息 HTML iframe 内各自初始化整包，否则生成事件和保存会重复执行。关闭实例时清理监听器、任务与 iframe。

服务器负责资源、原生请求/消息投影和持久化。浏览器持有一次任务对应的上下文快照，在每个生命周期阶段返回明确结果；没有运行实例时要报告模板运行时不可用，不能静默退回局部实现后仍报告整包就绪。浏览器重连需要重新绑定实例，迟到结果按 session、branch、revision 和 operation 拒收。

## 生命周期接入

1. 加载人物卡及资源，创建实例，初始化上游五个入口并加载设置。worldbook preload 和 initial variables 由上游执行。
2. 原生生成开始后，在明确的请求边界依次适配 GENERATION_AFTER_COMMANDS、WORLDINFO_ENTRIES_LOADED、GENERATE_AFTER_DATA、CHAT_COMPLETION_SETTINGS_READY。事件参数以固定版本上游处理器实际读写的结构为准，不只是广播同名字符串。
3. 模板对请求的修改回传为本次请求投影。需要验证最终 provider body，不能仅观察轨迹面板。
4. 正文返回后按上游消息处理事件执行；显示变化投影到前台；变量与正文修改通过原生提交接口。MVU 结算仍遵守既有事件事务，模板旧事件不得覆盖新一轮变量。
5. 编辑、重试、回退、重启、导入聊天分别提供对应快照和事件；不能只覆盖“新建对话→正常生成”。

DSH append-only Session 历史保持不变。上游的 chat 数组是兼容视图，修改经过原生领域操作提交，不直接改写 session.events。上游任意历史楼层永久重写、swipe 删除等语义与当前仅支持最后一轮替换的能力有差异；完成完整兼容需要逐项增加正式领域操作和恢复测试，不能另存一套独立聊天记录。

## 原生存储和服务接入

完整模板已具有正式 RPC：getFullPromptTemplateState、saveFullPromptTemplateState、saveFullPromptTemplateSettings。读取人物和绑定世界书，返回上游格式的聊天快照；设置保存在原有 Profile 命名空间。完整模板读取真实 enabled 配置，不把引擎存在等同于用户启用。

聊天变量、消息各 swipe 的变量、variables_initialized/is_ejs_processed 标记通过原生 Chat Persistence 和 Journal 保存。服务器使用已持久化的 stateRevision 作为基线，对照最新版本合并；无关并发键保留，同键冲突、聊天切换、正文/swipe 改变或 MVU 临时结算期间的保存拒绝。浏览器将保存回执合入当前对象，保留等待期间的新编辑。

正式服务提供清单内且哈希匹配的整包资源，包括设置 HTML、Monaco 和 worker。运行时文件尚不意味着默认启用：现有前台没有自动挂载整包，也没有把实际 provider 请求交给它。connectTemplateSession 已连接原生接口，供后续执行器使用。

浏览器原生持久化测试使用临时目录和真实 journal、真实宿主适配器，经 HTTP 保存后重新打开存储验证 hp=9；同时验证上游嵌套世界书模板输出 HP 9。正式本地服务只读验证了现有人物卡快照接口以及资源 HTTP 200，没有修改用户的游戏变量。

仍未完成：全局变量保存、正文永久改写的原生历史操作、实际模型请求与回复显示流程、前台实例挂载和设置入口、MVU 整体顺序验证。当前不支持的全局保存和正文修改明确报错，不能被计入完整兼容验收。


## 全局变量保存与真实模型复测（2026-09-09）

上游 `updateTokens` 在请求处理后异步写入 `LAST_SEND_TOKENS` / `LAST_SEND_CHARS`，旧宿主拒绝全局变动，因此普通请求也会阻断下一次保存。现在通过 `saveFullPromptTemplateGlobals` 写入既有 Profile 的 `prompt-template-variables.json`，与旧引擎共享同一存储。带读取基线的保存按变量合并、删除，同一变量冲突时原子拒绝；浏览器接收回执推进基线并保留等待期间的新编辑。聊天、全局变量、设置仍分别提交，不构成跨文件原子事务。

真实验证：独立浏览器整包运行时将 `getMessageVar("hp") + 1` 求值为 10，再将处理后的消息经正式 `generateTavernHelperRaw` 发送到当前会话配置的真实模型（未包含用户历史）。模型 2422 ms 返回 `{"marker":"dsh-global-399ac8f1-4660-4cbf-8224-ba73077dd7b6","hp":10}`。将返回数值交给测试实例的 `/ejs` 后，保存并重开原生存储读到 hp=10、revision=3，以及两个全局统计字段；再次保存也成功。

这是一条手工桥接的集成验证，未将真实用户聊天写入测试状态。测试实例的 token 计数服务使用字符数，统计值 105 只用于验证持久化，不代表真实模型 tokenizer 计数。正式前台自动挂载、回复渲染生命周期及完整人物卡流程仍待接入。

验证：全量 1772 项通过；重建整包后资源/正式路由相关 8 项通过。
