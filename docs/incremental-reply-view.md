# 正文视图的保守增量投影

普通 `getSession` 读取持久化会话时，正文与持久状态栏投影复用进程内缓存。存档格式、原始消息、脚本接口和完整历史保持不变。缓存最多保留 4 个会话、约 8 MiB 的序列化载荷估算值；不是 V8 堆内存上限。

- 同一存档 revision、相同规则和宏参数、相同剧情分支：复用投影。
- revision 前进：使用已有 journal 的 `readChangedSlice` 获取经过验证的变更索引；末端版本必须与本次读取的 Chat 完全一致。
- 追加或编辑消息：重算相关消息；用户行等结构变化影响推断轮次时重算后缀。消息变化后仍重新计算状态栏的跨消息关联。
- 没有消息变化的后台状态写入：复用消息及状态栏投影。
- 规则、身份、宏参数、分支变化，缓存淘汰或增量证据缺失/版本不匹配：完整重建。
- 临时草稿与直接操作响应：不依赖持久化 revision 缓存。

返回值仍是独立副本，避免调用者污染缓存。所有原始历史仍可读取；没有“只保留最近 N 轮”的截断。

这不是整个会话接口的 O(1) 改造。存档读取、Helper 完整上下文、响应复制/序列化及其他 UI 元数据仍按原流程处理。诊断包 `performance/summary.json` 的 `replyProjection` 提供重建、增量、复用和消息投影计数，帮助判断实际命中情况。

回归测试用原有完整投影作为对照，覆盖追加、旧消息编辑、用户行删除、身份/规则依赖变化、缓存隔离和真实 journal 证据丢失后的重建。
