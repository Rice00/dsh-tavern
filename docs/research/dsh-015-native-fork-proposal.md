# DSH 0.1.5 原生分叉适配提案

状态：待确认，未改生产编辑/回退实现。DSH 本体不修改。

## 已有证据

当前全量 1885 项，1874 通过、11 失败，失败围绕 assistant replacement。失败请求清理与恢复、导入后回退目标定位使用规范的新写入边界后通过；旧版这组 17 项全部通过。没有跳过或降低正文替换成功断言。

最小原生实验通过 SessionStore.fork 从上一闭合回合派生子 Session，再追加替代回合；Session.fromRestore 恢复后保留新正文，父 Session 事件逐项不变。只验证了内存原生分叉与序列恢复，尚未验证此策略下真实 Agent 请求、JSONL 持久化、工具回合及 UI 切换。

## 建议的行为变化

- Tavern 仍显示同一个游戏；编辑、重新生成或回退时，底层切换到新的原生 DSH Session。
- 旧 Session 保留为历史分支。DSH 原生会话列表/诊断中可能出现这些分支，不能承诺完全不可见。
- 回退：从目标 checkpoint 对应的闭合回合边界派生。
- 重生成：从旧回复所在轮开始前派生，重新运行该轮；成功后绑定新 Session，失败仍保持原会话。
- 编辑：从该轮开始前派生，按新 Session 的正式初始化协议重建玩家输入及编辑后的回复。若该轮含工具调用或其他无法无损重建的事件，必须先完成对应映射验证，不能偷偷丢弃。
- 后台同样从 checkpoint 派生或恢复，不能继续引用已废弃剧情的压缩摘要。

## 实施前必须验证的边界

1. 使用真实 Agent 与 JSONL 后端，证明编辑后的下一次请求仅含新正文，旧会话无变化；重启后绑定仍正确。
2. 用可恢复的绑定操作记录串联 Chat journal、Session 创建与切换；任何一步失败不使当前游戏指向半成品，不删除父 Session。
3. 保留工作目录、模型与运行配置、系统背景、附件引用、Frame、MVU checkpoint 和后台归属；不能仅复制 messages。
4. 前端重连切换会话，保留草稿并丢弃旧分支迟到结果；导出与诊断追踪父子关系。
5. 连续编辑/回退/重生成、压缩之后操作、重启恢复及工具回合分别验收。

这会扩大适配范围，改变现有“同一个 Session 中替换 Surface”的实现。它不是已经完成的替代方案。旧格式存档迁移另行处理，不能据此宣称已可直接打开旧存档。
