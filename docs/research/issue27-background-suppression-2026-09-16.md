# #27 后台页面只读查询阻塞

诊断包的性能汇总中，getBackgroundSuppressedTurns 共 48 次，平均 6952ms、最大 7958ms，47 次慢请求；getSession 最大 271341ms、syncSession 最大 272632ms。issue 提供的 CPU 采样和恢复会话分析未在本机原环境重放，不能把所有积压请求独立归因于该方法。

已修复：

- RPC 不再调用 agentRegistry.resume/dispose；仅读取已加载会话，未加载时返回此前缓存或空结果。
- 最多缓存 64 个会话的轮次结果，按会话对象、事件数和末 seq 判断失效。缓存用 WeakRef，不强持有完整 Session；以宿主事件追加不可变契约为前提。
- 合并替换区间后按事件查询区间，避免每个替换记录扫描整段历史；支持乱序 seq、旧版 start/end 和新版 startSeq/endSeq。
- 客户端共享同会话在途请求；上一请求结束后，运行状态下再等 15 秒刷新。空闲时只查询一次，运行状态或最新消息变化时补查。effect 销毁会取消后续计时，不再清空同会话已有结果。

未加载且没有缓存时，不主动恢复会话来重建隐藏轮次；会话加载后的后续刷新才得到完整结果。

验证：34 项相关测试通过，1 项本机 native host 边界测试因运行时条件跳过；客户端已重新生成并检查。新增 31564 条历史、249 个替换区间的复杂度测试在旧实现失败，修复后通过；另覆盖缓存命中、追加失效、会话替换、冷查询、读结果隔离、RPC 禁止恢复/释放，以及慢请求跨 effect 去重和空闲停止。

本机合成测量：31564 条事件首次扫描约 3.96ms；48 次缓存查询合计 0.047ms；48 次未加载缓存读取合计 0.018ms。此测量仅包含真实投影模块，未包含 HTTP、snapshotEvents 和原 Linux 环境；不声称群友实际请求已降至这些数值。
