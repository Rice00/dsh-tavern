# Issue #46：用确认协议接续脚本事件

此前父页把 15 秒无宿主写入或 60 秒总时长当成事件失败；服务端也从 start 开始计算绝对执行时限。成功回执的 HTTP 请求超时还会被捕获成脚本异常，再补发失败回执。慢回调和网络丢包因此可能覆盖真正的执行结果。

## 改动

- iframe 接收事件后先返回状态。同一 eventId 只排队一次；重复投递或查询返回当前状态，完成后重发原结果。父页接收结果并等待已接收的写入结束，再 ACK；ACK 后释放结果数据，保留去重身份到沙箱销毁。
- 父页定期发送只含 ID 的状态查询。只有查询返回 unknown 才重投原事件，不重复传送变量快照。持续响应的慢脚本没有总执行时限。无响应仍触发失联检测、关闭旧事件写入并销毁旧沙箱。
- Host 的执行时限改为可续租租约，eventId/runtimeId/leaseToken 三者匹配才可查询或续租。续租依据沙箱的实际响应，不能只凭父页在线。服务启动随机标识进入租约，避免重启后旧身份碰撞。
- 浏览器保留开始确认和完成回执的状态。start 丢包重试同一 start；完成回执丢包查询状态或补发同一结果，不能再发送相反的失败结果。执行和回执待确认期间，不领取另一项任务。
- Host 保留最多 1024 个已接受回执身份，不复制事件结果。重复完成请求只确认原来的交接，不重复完成草稿或变量提交。
- 完整模板引擎共享调度器，但有独立恢复协议；明确保留它原有执行策略。

## 恢复边界

执行 ACK 只确认浏览器把结果交给 Host，不代表变量已经提交。变量提交仍沿用现有 MVU pendingSubmission、delivery effect 保存点和 Story Timeline Settlement Receipt；断线后延期持久任务，重启从这些事实接续。内存执行回执丢失时不能猜测已成功，也不把普通事件变成新的持久队列。

去重保证针对同一沙箱的同一事件。进程崩溃后，尚未保存 effect 的 MVU 草稿可能需要重建；人物卡自行发送的外部网络请求不属于 Tavern 原子提交，不能承诺跨进程恰好一次。原有 branch/revision/lifecycle/swipe 验证保留。

本次不改 Prompt 内容、排列、历史投影或模型调用，不涉及 LLM 上下文缓存策略。

## 验证

- 调度器回归先复现缺少状态查询/续租与回执去重，再实现协议。
- 真实父页运行模块与真实 Helper bootstrap 互联，丢弃首个事件和首个完成回执，最终完成且回调只运行一次。
- 模拟时钟跨越原总时限，持续响应的脚本仍可完成；失联后拒绝迟到写入。
- start 回应丢失、完成回执已接受/未接受两种丢包、独立续租、取消后旧回调完成、重启后租约碰撞、MVU 正式持久任务恢复及重复回执均覆盖。
- 使用 `node bin/build-tavern-client.mjs --check` 和 `node bin/test-tavern.mjs` 检查生成产物及全量回归。
